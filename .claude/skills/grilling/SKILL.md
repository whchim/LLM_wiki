---
name: grilling
description: 对计划、决策或想法进行无情的连环追问。当用户想给自己的思路做压力测试，或用到了任何「拷问/追问/盘问」类触发词时使用。
---

对用户进行无情的连环追问，直到双方达成共享理解。把整个讨论映射为一棵**设计树**：每个决策都会分支出一系列依附于它的子决策。

按**轮次**推进这棵树。**前沿（frontier）** 是那些前置条件已敲定、现在就可以问的决策——也就是无需猜测尚未听到的回答即可提出的问题。在一轮里问完整个前沿：给每个问题编号，并附上你的推荐答案，然后等待用户回答，再进入下一轮。

每个问题按如下格式提出：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以是多段，包含多个选项>

➡️ <你的推荐答案>
```

每一轮用户的回答都会重塑这棵树：敲定的决策会把前沿向外推开，解锁那些依赖它的后续问题。重算前沿后进入下一轮。某个问题的答案若依赖于本轮中仍悬而未决的另一个问题，它属于**更晚**的轮次，而非本轮。

**查明事实是你的职责，永远不要抛给用户。** 当前沿某个问题需要来自环境的事实（文件系统、工具等）时，派发一个子 Agent 去找，不要为了任何你能自己查到的东西去问用户。也不必因此阻塞：正在进行的探查是一个未敲定的前置条件，所以只有它下游的问题才需要等子 Agent 汇报；其余前沿问题现在就可以问。**决策**是用户的：把每个决策摆到用户面前并等待。

当前沿为空时会话结束：设计树的每个分支都已遍历，没有任何东西被悄悄假设。在用户确认已达成共享理解之前，不要动手实施。
