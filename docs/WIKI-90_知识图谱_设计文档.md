# 知识图谱设计文档 v0.1

> 定位：知识层的**发现端**。编译把文档变成结构化条目、检索与问答让人找到已知的东西，
> 图谱回答另外两个问题——**这些条目之间是什么关系**、**哪些东西被反复提到却还没建**。
> 分层口径见 `docs/ARCH-00_项目定位与分层.md`；引擎侧见 `docs/WIKI-70`；问答侧见 `docs/WIKI-80`。

## 1. 问题：关系与缺口原先只有 Obsidian 看得见

Demo 期"图谱"是 Obsidian 客户端的本地能力（打开 `vault/` 看关系图）。云端多租户部署后：

1. 用户进不了 Obsidian（vault 在服务器上），关系视图**没有服务端实现**；
2. `[[wikilink]]` 指向不存在的条目（wiki 的"红链"）**没有任何地方被统计**——
   而这恰恰是最精确的知识缺口信号：不是"有人搜了没搜到"（`/search` 缺口），
   也不是"问了答不上来"（`/ask` 缺口），而是**知识本身自己说"我这里缺一块"**。

## 2. 目标架构

```
core/graph.py                从已编译 Markdown 派生图（不新增权威表）
   ├── 节点：NEXUS/**/*.md（可含 pending_review/）→ 条目（title/type/status/department/degree）
   ├── 边：frontmatter related_to  +  正文 [[wikilink]]  +  [文字](路径.md)
   └── 待建页面：被引用但解析不到目标的引用（红链），带引用次数与来源
        ▼
api/routers/graph_router.py   GET /graph（登录可见）、GET /graph/neighbors?path=
        ▼
frontend/src/pages/GraphPage.vue   SVG 力导向图 + 待建清单 + 孤立条目
```

**不落库的理由**：图谱是**可重建的派生视图**（与 `knowledge_entries`、embedding 同一性质），
文件仍是权威；规模是"每租户几千条目"，实时解析够快。真到十万级再上物化表 + 增量更新，
届时仍是"文件为权威、表为缓存"的同一套说法，不改变契约。

## 3. 三路关系来源与解析顺序

| 来源 | 说明 | 信号强度 |
|---|---|---|
| frontmatter `related_to` | 编译契约里的结构化关联（模型按契约给出，可校验） | 最强 |
| 正文 `[[wikilink]]` | `## 关联知识` 区块与行内引用，支持 `[[标题]]`、`[[标题\|显示]]`、`[[路径]]` | 强 |
| 正文 `[文字](路径.md)` | 显式相对链接（忽略 http(s) 外链与锚点） | 中 |

解析顺序（每一层都是真机语料暴露问题后才加的，见 §7）：

1. 目标带 `.md` → 先按**当前文件目录**解析（Markdown 链接语义，支持 `../`），再按知识库根解析；
2. 按 frontmatter `title` / 文件名主干精确匹配；
3. 剥掉**类型前缀**再试（`[[概念-新质生产力]]` → `新质生产力`）；
4. 目标是路径但前缀不完整（`概念/新质生产力.md`）→ 用**最后一段**匹配标题/主干；
5. 仍不解析 → 记进 `missing`（待建页面），**不丢弃**。

## 4. 待建页面：自增长的第二条燃料

`/search` 缺口来自"grep 零命中 + 向量相似度 < τ"（用户搜不到），`/ask` 缺口来自"答不上来"，
图谱的 `missing` 是第三条、也更精确：**被引用了 N 次但没建**。

真机验收（本地 130 篇企业语料编译出的 5 个条目）立刻给出 5 个明确待建项：
`中国式现代化 ×2`、`高质量发展 ×2`、`科技创新 ×2`、`AI Native企业治理 ×2`、`文件编码命名规范 ×2`。
按引用次数排序即补文档的优先级——这是可以直接派活的清单，而不是"再找找看"。

> 待建清单目前**只读展示**，没有一键建页/派单（见 §8）；自动建页也会违反
> "概念页必须人工放行"的既有边界，要做也只能是"生成待审草稿"。

## 5. 安全阀与口径

- `max_nodes`（默认 1500，接口上限 5000）：超限按路径序截断，并在 `stats.truncated=true`
  **如实标注**（不静默丢数据，前端显红字提示）；
- **范围对齐 Obsidian 的图谱口径**（三个开关）：

| 开关 | 默认 | 含义 |
|---|---|---|
| `include_meta` | ✅ 开 | **保留文件**（`index.md` / `log.md` / `SCHEMA.md`）——见 §6，它们是知识库自我描述的一部分 |
| `include_pending` | ✅ 开 | `pending_review/` 待审概念页 |
| `include_raw` | ❌ 关 | `RAW/` 原始语料（`kind=raw`，另行着色）；打开会把未编译原料混进来淹没知识层，需要时才开 |

- 节点带 `kind`（`concept`/`resource`/`research`/`glossary`/`index`/`log`/`schema`/`raw`/`missing`）
  与 `is_meta` 标记，前端据此着色、过滤、统计（`stats.by_kind`）；
- **运行期目录不进图**：`_triggers/`（触发纸条）、`_suggestions/`、`tenants/`（租户子树）不是知识内容；
- 按租户分区：扫描根走 `paths.kb_root()`（L3.5），两个租户的同名条目各成一张图；
- 权限：登录即可查看（图谱不暴露比「全部条目」更多的信息，正文预览仍走 `/entries/content`）。

## 6. 保留文件必须出现在图上（v0.1 的错误决定，已纠正）

v0.1 把 `index.md` / `log.md` / `SCHEMA.md` 当"非条目"**排除**出图谱，理由是"索引度数最高、
还会造出假缺口"。用户实测后指出这与 **LLM Wiki 编译范式的原始理念**不符：

> 保留 `index.md`（渐进式目录，编译时逐次更新）和 `log.md`（审计日志，Phase 2 起记录操作事件）
> ——PRD WIKI-00 §Reserved Files

**在编译范式里，索引与日志不是噪音，而是知识库的自我描述**：索引回答"这里有什么"，
日志回答"它是怎么、何时变成这样的"。把它们从图上抹掉，等于把知识库自己的骨架藏起来。

正确做法是**保留 + 分类**（而不是隐藏）：

- 节点 `kind=index/log/schema`、`is_meta=true`，中文显示名为「知识库索引 / 编译日志 / 知识库规范」；
- 索引因列出全部条目而**度数最高**——这是**事实**，不该用排除来抹平；前端可一键过滤；
- 索引写的是 `[[概念-新质生产力]]` 这种**带类型前缀**的 wikilink：靠 §7 的解析链正常解析到真实条目，
  **不再产生假缺口**（v0.1 那些假缺口是解析缺陷，不是"索引不该上图"）。

### 6.1 顺带补齐：`log.md` 之前根本没人写

真机检查发现 `NEXUS/log.md` 是 **0 字节**——`init.sh` 只建了空文件占位，
**没有任何代码写它**，PRD 要求的"Phase 2 起记录操作事件"从未实现。本次补齐（`core/ops.append_log`）：

- **编译**：成功一行（`RAW/x.md → NEXUS/资源/x.md（资源 1 + 概念 5）`）、失败一行（带原因）；
- **审核**：人工放行 / 驳回 / 重提各一行（文件侧镜像 `audit_logs` 与决策链）；
- **上传**：每个批次一行（多少篇、什么分类、谁提交）；
- **append-only**：历史行永不改写；写失败返回 `False`、**不抛异常**（日志不能阻断主流程）。

真机验证（本地真实语料跑队列编译）：`log.md` 从 0 字节变成 7 条真实事件，含一条模型超时失败与
数条成功（如 `第二篇_建设现代化产业体系… → NEXUS/资源/建设现代化产业体系 巩固壮大实体经济根基.md（资源 1 + 概念 5）`）。

## 7. 前端：Obsidian 同款渲染与交互（v0.2 重做）

v0.1 是手写的简化力导向 + 固定 SVG 视口，用户实测指出三个硬伤：**不能缩放**（看不全也看不细）、
**悬停没有邻域高亮**（Obsidian 那种"点谁亮谁"）、整体观感不像图谱。v0.2 换成 Obsidian 自己用的技术栈：

| 能力 | 实现 |
|---|---|
| 物理布局 | **`d3-force`**（`forceLink` + `forceManyBody` + `forceCenter` + `forceX/Y` + `forceCollide`），与 Obsidian 同源的力导向模型 |
| 渲染 | **canvas 2D**（`devicePixelRatio` 适配），几十到几千节点都能流畅重绘 |
| 缩放/平移 | 滚轮以**光标为中心**缩放（0.15×–6×）、空白处拖拽平移、`适应视图` 一键框住全图 |
| 拖拽节点 | 拖动即固定（`fx/fy`）、`释放固定` 一键解绑——"我放哪儿它就在哪儿" |
| 悬停高亮 | 悬停/选中的节点 + **1 跳邻域**高亮连线并显示标签，其余淡出；右上浮层给标题/类型/部门/连接数，邻接可点击跳转 |
| 物理旋钮 | 中心力 / 斥力 / 连线力 / 连线距离 + "避免重叠"——Obsidian 图谱面板同款四项 |
| 过滤 | 按 `kind` 多选过滤、三个范围开关、标注策略（自动/总是/隐藏） |
| 定位 | 搜索标题或路径 → 平移+缩放到该节点并选中 |
| 待建页面 | 作为**虚线空心节点**参与仿真（Obsidian 的 unresolved links 同款），右侧另有可读清单 |

配色：概念=绿、资源=蓝、研究=紫、术语=青、**索引/日志/规范=橙黄系（保留文件）**、RAW=灰、待建=红（虚线），
图例带各类型计数。

### 7.1 v0.1 真机暴露并修掉的四个解析问题（仍然有效）

| 现象 | 原因 | 修法 |
|---|---|---|
| `index` 度数最高，压过真实概念 | 索引列出全部条目（**这是事实，不再当成问题**） | 保留为 `kind=index` 节点 + 前端可过滤 |
| 冒出 `概念-文件资产数字化` 等假缺口 | 索引工具写的 wikilink 带类型前缀 | 解析时剥前缀重试（`概念-/资源-/研究-/术语-`） |
| `https://example.com/a.md` 进了待建清单 | 外链以 `.md` 结尾被当成条目路径 | 外链（含 `scheme:`）一律不进图 |
| 相对链接解析不到 | 只按知识库根解析，忽略 Markdown 的相对语义 | 先按当前文件目录（含 `../`）解析，末段兜底 |

### 8.1 视觉自检工具（`frontend/tools/graph_snapshot.mjs`）

图谱"丑不丑"是审美问题，**读代码判断不了**。该工具用与 `GraphPage.vue` 相同的参数把真实
`/graph` 数据渲染成独立 HTML（浅色 + 深色），再用无头 Edge 截图——本轮的三个关键结论都是靠它看出来的：

| 截图暴露的问题 | 根因 | 修法 |
|---|---|---|
| 全图只有中间一小团、大量空白 | 孤立条目被摆在**大半径环**上，包围盒被撑大，`fit` 把主簇缩小 | 只让**有连接**的节点进物理；孤立条目按主簇包围盒外缘 `+110` 摆放 |
| 完整视图一片"星尘" | 109 个节点里有 15 个连通分量，**无上限的全局斥力**把每个小簇摊开 | 斥力加 `distanceMax=260`（只做局部排斥）+ 弱向心力 `0.05` 把远处小簇拉回 |
| 标签糊成一团 | 用"度数≥4"当显示阈值，而 215 条边分给 109 个节点（平均度≈4）几乎人人命中 | 改成**标签预算**：保留文件 + 被引最多的 8 个待建 + 度数最高的条目，共 22 个；悬停邻域另算 |

工具同时打印**布局指标**（连通分量数 / 重叠对数 / 平均边长 / 包围盒跨度），比肉眼更早发现回归：
重叠必须为 0；分量数一高就得靠 `distanceMax` + 向心力收敛。改布局参数前先跑它。

### 8.2 页面 E2E 冒烟（`frontend/tools/page_smoke.mjs`，`npm run smoke`）

快照脚本验证的是**布局算法**，验证不了**页面有没有把图画出来**。v0.3 就踩了这个坑：
真机上画布**全空**，而统计行显示"节点 0 · 关系 215"——

> 根因：Vue 组件里 `simNodes` 用了普通 `let` 数组，而 `visibleNodes` 是由它派生的 `computed`。
> 模板在**首屏（数据还没到）**就要读 `visibleNodes.length` 渲染统计行，于是 computed 把"空数组"
> 永久缓存下来；数据到达后 `simNodes` 是换了引用，但没有任何响应式依赖被触发，画布永远画空的。
> v0.2 侥幸没暴露：那时第一次读取恰好发生在赋值之后（属于同一个 bug，只是刚好没触发）。

修法：状态一律用 `shallowRef`（`simNodes` / `simLinks` / `simDegree` / `labelsRef`），模板与 computed 才追得动。

冒烟脚本用系统已装的 Edge（`playwright-core` + `channel: 'msedge'`，不额外下浏览器）：
登录拿 token → 写 localStorage → 打开工作台 → 切「知识图谱」→ 等布局跑完 → **对 canvas 采样统计
非背景像素占比**（必须 > 0.2%）+ 读统计行 + 收集控制台错误 + 截图 `tools/_shot_page.png`。
真机结果：`节点 109 · 关系 215 · 待建 64`，非背景像素 5.04%，零控制台错误。

> 这类"状态不是响应式 → 界面静默空白"的问题，**单元测试与快照都抓不到**，只能靠真页面冒烟。
> 改任何一页的渲染状态后，跑一次 `npm run smoke` 比读代码靠谱。

## 9. 已知取舍与未完成项

1. **图谱不落库、无增量**：每次请求全量解析（几千条目内可接受）；百万级需物化表 + 增量。
2. **没有图算法**：只算度数（degree），没有社区发现/中心性/PageRank——"哪个概念最核心"
   目前只是"连接最多"，不是"影响力最大"。
3. **待建清单只有只读展示**：没有一键生成待审草稿、没有派单/认领、没有与 `/search`、`/ask`
   缺口合并排序（三条缺口来源目前各看各的）。
4. **边没有权重与置信度**：`related_to`（模型给的）与行内 wikilink（顺笔一提）在图上等价；
   想要"强关系"需要按来源类型加权或引入人工确认。
5. **保留文件度数天然偏高**：索引列全库，视觉上是最亮的节点；前端可过滤，但还没有
   "把保留文件排除出中心性统计"这类更细的口径。
6. **图谱内不能编辑**：不能在图里连线/建页（知识只能从文档编译进来，符合"模型不直接改事实"的边界）。
7. **截断策略简单**：超限按路径序截断，不做"先保高度节点"这类有损但更聪明的取舍。
8. **只画本租户**：跨租户的公共知识层（如果有）不做展示——多租户边界优先。
