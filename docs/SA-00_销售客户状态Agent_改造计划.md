# 销售客户状态 Agent 改造计划

> 版本：v1.0  
> 制定日期：2026-09-08  
> 执行规则：阶段必须按顺序推进。每完成一个阶段，暂停并由项目负责人确认后，才能进入下一阶段。  
> 当前约束：暂无合法可用的真实销售数据，因此第一版只证明工程闭环、边界控制和可回放评测，不宣称真实业务效果。

## 一、改造目标

将当前偏通用的 LLM Wiki Demo，收敛为一个面向销售跟进的生产形态 Agent 原型：

> 销售洽谈记录 → AI 提取证据 → 生成客户状态变更建议 → 负责人确认 → 更新当前状态 → 支持有效期、撤回、追溯和回放。

第一版不追求支持最多输入类型，而追求在有限边界内稳定完成一个可验收流程。

## 二、非目标

第一版暂不承诺：

- 真实企业销售效果或成交率提升；
- 直接接入公司生产数据；
- 同时支持录音、图片、网页、聊天记录等全部输入；
- AI 自动替代老板或销售负责人做最终决策；
- 一开始建设多部门通用平台。

## 三、目标闭环

```text
销售文字记录
    ↓
原始证据保存（不可覆盖）
    ↓
AI 提取客户状态、证据和下一步行动
    ↓
确定性校验、置信度和风险分流
    ↓
负责人确认 / 修改 / 驳回
    ↓
写入当前客户状态
    ↓
过期、撤回、状态变化形成新的事件
    ↓
查询当前状态与完整历史
```

### 阶段 1：领域模型与知识分层

**目标**：让客户状态成为业务中心，而不是继续围绕普通 Markdown 文档堆功能。

**设计对象**：

- `Customer`：客户主体；
- `Conversation`：一次销售洽谈；
- `Evidence`：原始文字和来源信息；
- `StateProposal`：AI 生成的状态建议；
- `StateDecision`：负责人确认结果；
- `CurrentState`：当前有效状态视图；
- `StateEvent`：状态变化、过期和撤回事件。

**核心原则**：

- 原始证据不可被 AI 覆盖；
- AI 判断与人工确认分层保存；
- 当前状态由事件历史推导或更新；
- 撤回采用新事件，不删除历史；
- 每个状态必须有来源、时间和有效期。

**交付物**：

- 领域模型文档；
- 数据库 ER 图；
- 状态事件时序图；
- 旧 `resource/concept` 模型到新模型的映射方案。

**退出标准**：能够解释任意当前客户状态的来源、确认人、更新时间和历史变化。

**确认点 B**：你确认领域模型和知识分层后，才进入阶段 2。

**完成记录（2026-09-08）**：负责人已确认领域对象、事件事实边界、知识分层和敏感数值独立受限表方案。阶段 2 已开始。

### 阶段 3：确定性预处理与安全门禁

**目标**：在调用 LLM 前后建立可控边界，减少成本并防止不可信输入直接影响状态。

**主要工作**：

- 输入格式、长度、编码和敏感信息检查；
- 客户标识和洽谈时间规范化；
- 重复记录去重；
- 证据字段完整性校验；
- 状态枚举和状态转移合法性校验；
- Prompt injection 和指令混入检测；
- 不合格输入进入人工处理队列。

**交付物**：

- 确定性预处理模块；
- 安全规则清单；
- 输入异常测试集；
- 成本前置过滤统计。

**退出标准**：不调用 LLM 也能拦截格式错误、缺少关键字段、重复记录和明显越权输入。

**确认点 D**：你确认安全边界和异常处理策略后，才进入阶段 4。

**当前进度（2026-09-08）**：已完成纯确定性销售文字预处理模块和专项测试，待阶段 3 验收。当前不会进入阶段 4。

**实现记录**：

- `streamlit_app/sales_preprocess.py`：校验必填字段、脱敏客户标识、中文范围、长度、时区和未来时间窗口；

### 阶段 4：Agent 状态判断与结构化输出

**目标**：让 Agent 只负责有限的判断，不直接执行不可逆业务写操作。

**Agent 输出必须包含**：

- 客户标识；
- 当前状态和建议新状态；
- 置信度；
- 原文证据引用；
- 判断理由；
- 下一步行动建议；
- 有效期；
- 是否必须人工确认；
- 模型、Prompt 和版本信息。

**主要工作**：

- 设计最小 Prompt；
- 接入现有 output schema 思路；
- 对不确定、冲突和证据不足进行降级；
- 让低置信度结果进入人工审核；
- 禁止 Agent 直接覆盖原始证据和确认事实。

**交付物**：

- Agent service；
- 结构化输出契约；
- 正常、冲突、证据不足和恶意输入测试；
- LLM 调用失败和重试策略。

**退出标准**：Agent 只能输出受约束的状态建议，任何越界字段或不一致结果都不会进入确认流程。

**确认点 E**：你确认 Agent 输出契约和失败语义后，才进入阶段 5。

**当前进度（2026-09-08）**：已完成 Agent 输出解析、确定性契约校验和建议写入适配器，待阶段 4 验收。当前不会进入阶段 5。

**实现记录**：

- `streamlit_app/sales_state_agent.py`：拒绝非 JSON、未知字段、客户上下文不一致、非法状态转移和不可定位证据；
- 校验置信度、人工确认标识、`won` 强制人工确认、风险标识、有效期以及模型/Prompt 版本；

## 六、最终验收标准

```text

→ 展示下一步行动和有效期
→ 状态过期或错误时可撤回/更正
→ 全过程可审计、可回放、可统计成本
```
