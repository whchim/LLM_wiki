# 销售事实澄清 Agent：角色化工作台

> 阶段：5 ｜ 状态：已实现，等待负责人走通验收

## 1. 目的

工作台将销售录入、Agent 澄清和负责人确认拆开：销售只补充其能确认的事实；负责人查看结果和证据；状态变更仍由既有状态机和负责人决定接口执行。

## 2. 页面与权限

| 页面 | 普通用户 | 审核者 / 管理员 | 关键操作 |
|---|---|---|---|
| 销售澄清 | 仅自己的会话 | 可进入 | 提交脱敏纪要、回答实际追问；**澄清完成后生成状态建议** |
| 澄清审核 | 不可进入 | 全部会话 | 查看事实、归因、证据、缺口、成本与转人工状态；**处置转人工会话**（补充事实后重开 / 关闭并记录原因） |
| 销售客户状态 | 不可进入 | 待确认建议 | 确认、修改或驳回建议，查看状态事件时间线 |

服务端不信任前端的提交人字段。`POST /clarifications/intake` 从 JWT 获取当前用户，并在幂等重放时先做访问校验，避免通过重用幂等键读取或改写他人记录。

**删除（归档）仅管理员**：澄清会话与其状态建议的删除是软删除，只有 `admin` 可执行，恢复同样仅管理员。普通销售与审核者调用一律 403。

## 3. 销售录入门禁

销售提交字段为客户脱敏标识、发生时间、来源、纪要正文与幂等标识。后端在写入前执行：

- 仅允许中文文本、受限来源枚举和带时区的发生时间；
- 拦截明显 Prompt injection、个人信息、密钥和内部标记；
- 金额、报价、预算、折扣和数量必须由受控加密器保存到独立数值表；当前部署未配置该加密器时，包含这类精确数值的纪要会被拒绝；
- 纪要正文只保存替换后的数值引用，供 Agent 使用的上下文不包含精确数值；
- 相同幂等标识返回既有会话，不重复创建证据。

## 4. 会话展示规则

- 每轮最多显示两个实际持久化的问题；回答只能提交给该轮真实问题 ID；
- 原纪要、Agent 输出和销售回答均为追加记录，页面没有覆盖或编辑入口；
- Agent 失败、契约失败、达到第二轮仍需追问时，页面展示"转人工审核"；
- 转人工会话有**闭环出口**：审核者可「补充事实后继续」（还有 Agent 运行预算时）或「关闭会话」（原因必填，落库并进审计）——不再出现"看得见但动不了"；
- 轮次口径（方案 A）：`max_rounds` 是**最多追问轮数**（默认 2），追问用尽后仍允许一次**收尾判定**；**最后一轮追问可正常回答**。人工不得加轮次：`round_count > max_rounds`（询问与收尾都完成）时只能关闭；
- 人工处置只动**会话与回答**，绝不写客户状态——客户事实仍只能经状态建议 → 负责人确认 → `state_events` 写入（SA-02/SA-11 事实边界）；
- 审核页展示事实、归因和精确证据位置，不将模型解释直接标为客户已确认事实；
- token 与耗时来自 `clarification_turns`，无调用记录时不展示虚构成本。

## 5. 人工验收路径

1. 用普通销售账号提交不含精确数值的脱敏纪要，确认创建会话且重复提交不增加证据；
2. 通过受控 `ModelPort` 执行方写入一轮 `needs_clarification` 输出，确认销售只能回答自己的问题；
3. 以审核者账号打开“澄清审核”，核对事实归因、引用、缺口、回答和成本；
4. 让会话达到轮次上限或注入一次契约失败，确认状态变为“转人工审核”；
5. 以审核者账号处置该会话：轮次未用尽时「补充事实后继续」应重开并允许再跑一轮；轮次已用尽时只能「关闭会话」，关闭原因记录为 `resolution_note` 并在卡片可见；普通销售账号调用该接口应返回 403；
6. 准备一个独立 `StateProposal`，确认负责人在“销售客户状态”查看中文状态和证据时间线后再决定。
7. 把会话推进到「可生成建议」，点「生成状态建议」→ 到「客户状态」确认该建议 → 核对当前状态已更新、状态事件时间线新增一条（端到端闭环）。

## 6. 状态建议衔接（最后一公里，v0.4 补齐）

澄清走到 `ready_for_proposal` 后，工作台给出「生成状态建议」；**已转人工（`needs_human_review`）的会话同样可以生成**——否则"转人工"是死胡同：人工被叫来了却没有可判断的对象。

- **生成规则是确定性的**（`core/sales_state_rules.py`，不调模型）：按 SA-01 的**最低证据要求**判断事实能支撑哪些状态，再按**状态机逐级推进**（不跳跃）选定目标；证据不足或正负信号冲突 → 标 `needs_review`，**不猜测状态**。
- **判定引擎与成本纪律（v0.8 接线 LLM 复核）**：入口参数 `mode` 三档——`auto`（默认）、`rules`（强制规则）、`llm`（强制模型）。**规则能给出 `propose` 时绝不调模型**（关键词能命中的情形不需要付一次 LLM 成本）；只有规则给不出结论（证据不足 / 信号冲突——正是关键词覆盖不到的模糊表述）才请**状态 Agent 复核**（`prompts/sales_state_prompt.md`，SA-01 §8 输出契约）。`mode=llm` 时模型不可用直接 409（不静默降级）；`auto` 下模型不可用或未过契约 → **回退规则结论**，响应标 `used`（`rules`/`llm`/`llm+human_review`）与 `llm_error`，工作台用业务语言提示「本次结论来自规则判定」。
- **转人工会话强制 `needs_review`**：自动路径既然没能得出结论（模型/契约失败或证据不足），服务层把规则推断的结论降级为"仅供负责人判断"（置信度 ≤0.5、补 `low_confidence`、摘要注明转人工原因），**不把"没判出来"包装成"建议推进"**。
- 结论落 `state_proposals(status='pending')`，出现在负责人工作台「待确认建议」；负责人确认/修改/驳回后，才经 `state_decisions → state_events` 写入事实。
- **幂等**：同一洽谈已有待确认建议则复用，不重复创建；`open`（仍在澄清中）会话拒绝生成。
- 证据引用允许来自**追加回答**（`source=question-N`，偏移相对该回答文本）——这是澄清流程的常态。
- **关闭会话 ≠ 交付负责人**：关闭只结束本次澄清记录；要让负责人判断，必须先「生成建议交负责人」。
- **交接状态可见**：会话详情报 `pending_proposal`（建议阶段 + 类型），工作台据此显示「已交负责人：建议「X」待确认」，而不是看起来毫无变化。
- **确认结果可见**：「客户状态」页新增**客户当前状态总览**（`GET /customer-states/customers`：阶段 + 生效/有效期 + 待确认建议数）；负责人确认建议后自动落到该客户的结果视图（新阶段 + 刷新后的事件时间线），解决"确认完没有下文"。

## 7. 归档（软删除）：仅管理员

清理测试数据/误建记录的出口，规则是**软删除 + 权限收紧 + 不动事实**：

| 项 | 规则 |
|---|---|
| 权限 | `DELETE /clarifications/sessions/{id}` 与 `POST /clarifications/sessions/{id}/restore` **仅 admin**（销售本人与 reviewer 均 403） |
| 范围 | 归档会话**及其产生的状态建议**；追问/回答不单独标记（只通过会话读取，会话归档即不可见） |
| 方式 | 写 `deleted_at` / `deleted_by`，不 `DELETE` 行；所有读取路径默认排除已归档（`include_deleted=true` 仅管理员可用） |
| **不动的部分** | **`state_events` / `state_decisions` 永不删除**——客户事实只能追加更正/撤回/过期（SA-02）；归档后客户当前阶段与事件时间线完全不受影响（有测试锁定） |
| 可逆 | 管理员可恢复；恢复后会话与建议重新回到列表 |
| 留痕 | 删除与恢复都写 `audit_logs` + trace |

> 设计理由：**状态事件是事实，澄清会话是过程**。事实只能被新事实覆盖，过程可以归档——这条边界让"这个客户为什么是已接触"永远可追溯，即使中间的过程记录被清理。

## 8. 未完成项

- **模型判定质量未做真实评测**：LLM 复核路径已接线，但只保证**契约与回退**（契约校验、偏移由服务端重定位、失败回退规则），模型本身的状态判定准确率尚未用样本量化；负责人修正率、模型与规则的分歧率仍待积累（沿用 SA-04 的合成口径，不得对外称真实准确率）。
- 没有把澄清结果**自动**写入客户状态——这是持续保留的边界：`state_events` 只由负责人确认写入。
- 状态 Agent 的提示词版本管理（`prompt_version` 已入库，但缺版本对照与回滚流程）。

（已接通项：澄清 Agent 与状态 Agent 的真实模型供应商都走 `ModelPort`（DashScope OpenAI 兼容端点，`MODEL_API_KEY`/`DASHSCOPE_API_KEY`）；澄清结论 → 状态建议（规则 + 模型复核）已连通。）
