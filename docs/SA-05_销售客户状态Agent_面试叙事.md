# 销售客户状态 Agent 面试叙事

## 一句话定位

这是一个面向销售跟进的生产形态 Agent 原型：它不让模型直接改客户事实，而是在确定边界内提取证据、提出状态建议，由负责人确认后追加状态事件。

## 面试演示链路

1. 提交一条中文销售洽谈文字记录；
2. 预处理拦截缺字段、异常时间、Prompt injection 和未保护敏感数字；
3. Agent 输出带版本、置信度和可定位证据的状态建议；
4. 负责人查看风险和下一步，确认、修改或驳回；
5. 查询当前状态和完整历史；
6. 演示过期、撤回、更正和冲突分流；
7. 运行 36 条 synthetic 回放，展示拦截率、契约通过率和 token 估算。

## 三个关键取舍

- 规则明确的部分交给程序，语义不确定的部分交给模型；
- `StateEvent` 是事实唯一写入口，`CurrentState` 是可重建投影；
- 结果优先给老板看，证据和历史按需展开，复杂过程不阻塞确认动作。

## 不能夸大的内容

不能说已经证明真实销售转化率提升，也不能把 synthetic 回放的契约通过率说成 LLM 语义准确率。真实试点前仍需要脱敏业务数据、人工标注集、成本基线和并发/合规验证。
